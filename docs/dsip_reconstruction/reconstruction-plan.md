## 3. 新增统计量（本轮要求）

四个新统计量对应四个审稿条目，**定义必须一次定死**，避免事后挑口径。

### 3.1 最大加速度（R2-3）

| 项 | 内容 |
|---|---|
| 定义 | 由**执行轨迹**差分：`a_i(t) = (v_i(t+Δt) − v_i(t)) / Δt`，`Δt = 0.1 s` |
| 报告 | 分布 `p50 / p95 / p99 / max`（m/s²），并单列**超过 vType 阈值**的样本数：`a > accel = 1.0`、`a < −decel = −4.5` |
| 必须区分 | **指令加速度**（规划器下发的速度/位置变化）vs **实际加速度**（SUMO 物理上限之后） |
| 为什么重要 | DSIP 用 TraCI 直接改位置（`main.tex` L392）；若"位置控制"导致 `a` 超过 4.5 m/s²，那就是 R2-3 要的实证 |

### 3.2 加加速度（jerk，R2-3）

| 项 | 内容 |
|---|---|
| 定义 | `j_i(t) = (a_i(t+Δt) − a_i(t)) / Δt`，单位 m/s³ |
| 报告 | `p50 / p95 / p99 / max` 与 RMS |
| 必须披露 | 0.1 s 差分会**放大**离散噪声 ⇒ 同时报"原始差分"与"0.3 s 滑动平滑后"两套，并说明用的是哪套 |
| 判定 | 乘用车舒适性常用阈值 `|j| ≲ 2–3 m/s³`；只作对照，不当作本方法的判据 |

### 3.3 通信时延 / 丢包敏感性（R2-5）

| 项 | 内容 |
|---|---|
| 扫描 | 延迟 `{0, 50, 100} ms`（对应 R2 建议的 50–100 ms）× 丢包 `{0, 1, 5} %` |
| 老化模型 | **必须写死**：固定延迟（same offset）或 随机延迟 `U(0,d_max)`；丢包时规划器沿用**上一帧**状态，并记录 `state_age` |
| 随机性 | 延迟/丢包用一个**独立于交通流的种子**，记录在 manifest |
| 指标 | 论文四项指标 + 近距/急减速 + **相对无通信损伤的退化率** |
| 红线 | 不得为了"看起来稳"而隐藏丢包帧；每一帧 `state_age` 必须进原始日志 |

### 3.4 CBS 崩溃兜底分析（R2-4）

分两半，缺一不可：

**(a) 统计**：单次 CBS 查询耗时分布（`p50/p95/p99/max`）、搜索树深度、**400 ms 预算下的超时率**
（按密度分层）。注意：**不得**把"一次网络前向"当作一次完整规划查询上报
（历史 7.75 ms 的说法已在 `AGENTS.md` 标注为不可复现口径）。

**(b) 回落机制**：查询超时/无解时系统**实际做什么**。可选且必须如实登记其一：
- 沿用上一拍计划（hold-last-plan）；
- 降速至安全停车（safe-stop）；
- 降级为 FCFS 预约。

**要求**：机制必须是**代码里真实存在**的，不能事后描述；每次触发都要落日志（时刻、车辆集合、
原因、采取的动作），并统计**触发率**与**触发后的安全/效率影响**。

## 3.5 转向比敏感性研究（R1-M3，作者 2026-11-14 指定）

审稿人的 concern 是**敏感性**，不是要一个更优的比例。因此只加**两组**、且**总需求不变**：

| 组 | L : S : R | 用途 |
|---|---|---|
| 基线 | **1 : 2 : 1** | 稿件 Table I / `generate_flows.py` 现行口径 |
| 新增 A | **1 : 1 : 1** | 左转占比提高（最不利情形） |
| 新增 B | **1 : 2 : 2** | 右转占比提高 |

**必须固定不变**（否则测的是需求而不是转向比）：

- 每个进口的**总到达率**与 Table I 该密度一致（5 档密度仍取原值）；
- `μ = 3600/(n·d)`、`normal(μ, 1.0)` 的离散方式、seeds、1000 s、0.1 s、`types.typ.xml` 全部不变；
- **只改** `straight : (left, right)` 的分配。

实现方式（待做，**不启动**）：

1. `scenarios/flows/generate_flows.py` 增加 `--ratio {121,111,122}`；
   输出 `scenarios/flows/lanes{L}_d{D}_r{121,111,122}.rou.xml`，**不覆盖**现有 15 个文件；
2. 因为右转不参与协调（无内部冲突点），1:2:2 会显著改变"协调类车辆"的绝对量，
   报数时必须同时给出**绝对车辆数**与**占比**，不能只给百分比；
3. 指标：论文四项 + 完成率（计划侧）/ 完成率（交通侧，若可执行）。

**依赖与顺序**：DSIP 侧的这一组需要重建后的模型才能跑（S7 之后）；
但 **PSL/FCFS 侧的同一组可以在不重建 DSIP 的前提下先做**（只改 flow 文件），
建议作为"能先回答多少就先回答多少"的部分——需作者确认后再动。
