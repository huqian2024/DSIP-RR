## 2. 逐项说明（为什么推荐这个值）

### D1 安全间隔 `Δt_safe` — 推荐 2.0 s
- **含义**：两辆车占用同一资源之间必须留出的最小时间差。
- **为什么 2.0 s**：`types.typ.xml` 里 `tau="2.0"`，即 IDM 的期望车头时距就是 2 s。
  用同一个数当资源间隔，**FCFS 的保守度就与车辆跟驰模型同源**，可以在论文里一句话自证，
  不需要额外调参。
- **影响**：Δ 越大 → `UNDETERMINED` 越少、越安全、吞吐越低。0.5 s 会接近"贴着走"，
  在 1 s 步长下几乎无法实现（故与 D6 联动）。

### D2 控制区 `L_ACZ` — 推荐 28 m
- **含义**：车辆进入距停止线 `L_ACZ` 处时提出预约请求。
- **为什么 28 m**：`v_max × tau = 13.9 × 2.0 = 27.8 m`，与 D1 同源。请求到停止线约 **2 s**，
  足够完成一次决策（D6 下是 20 个步）。
- **为什么不取进口边全长**：83–90 m 会让请求过早提出、ETA 噪声被放大（Shadow 已观测到
  请求→进入跨度 1–15 s）。
- **影响**：太短 → 来不及决策，车辆在停止线前排队；太长 → ETA 误差大。

### D3 资源粒度 — 推荐"内部 via 车道 + 出口车道"
- **含义**：资源 = 一条 lane；冲突关系 = 两条 movement 是否共享同一 lane ID。
- **为什么必须含出口车道**：本仓库已实测——**无控制**时 15 组车流 100 s 内全部碰撞，
  **100% 在出口车道汇流处**、交叉口内部为 0。只预约交叉口内部**不足以**防碰撞。
- **为什么不用 movement 级**：movement 级无法表达"两条 movement 共用一条出口 lane"。
- **代价（必须写进论文）**：这是**最保守**的口径，会显著抬高 FCFS 延误。
  因此 FCFS 数字应被表述为"保守上界"，而不是"FCFS 的最好表现"。
- **附带好处**：只有这个口径能对 R2-3 说"我们证明了同车道不同时占用 → 无重叠"。

### D4 清空判定 — 推荐"观测 + 时间窗"取 and
- Shadow 阶段有 **11 辆车**在"占据方同一步清空"时驶入 → 说明纯观测判定会漏掉安全余量。
- 取 and 的代价是吞吐略降；但**两者不一致的次数本身是有价值的诊断量**（可报告）。

### D5 控制手段 — 推荐先 `setStop`
- `setStop(veh, laneID, pos)` 语义就是"在停止线停住，等批准"，最接近 Dresner–Stone。
- **副作用**：会写 `stopTime`，污染 `tripinfo` 的部分字段 → 所以 D9 要用**自采指标**。
- **不做的事**：不用 `setSpeed(0)`（绕过跟驰安全校核，可能造成车体重叠）；
  `slowDown(0,1step)` 作为后续优化项，需先实测其安全语义。
- **前置验证**：先在**单冲突对**（例如 `flow_we` 直行 vs `flow_se` 右转 → `center2east`）上验证
  批准/拒绝确实生效，再扩大。

### D6 步长 — 推荐 0.1 s
- 与论文一致；`400 ms 刷新 = 每 4 步`；1000 s = 10000 步。
- 0.1 s 下 FCFS 决策每步刷新一次，12 个 movement 的纯 Python 开销可忽略。

### D7 ETA 模型 — 推荐混合式
- `ETA = t + d / max(v, 1.0)`，并强制 `ETA ≥ t + d / v_max`（物理下界）。
- `v ≈ 0` 时用 `accel=1.0` 估起步加速度（`types.typ.xml` 的真实值），避免 ETA 爆掉。
- 明确标注为**近似**，并在论文里写清。

### D8 死锁 / 平局 — 推荐"字典序 + 不 hold-and-wait"
- 车辆在进口等待时**不得持有任何资源预约** → 结构性排除循环等待。
- 平局用 `(request_time, vehicle_id)`（`queue.py` 已实现，无需改）。
- **不加 aging**：会给 FCFS 引入非 FCFS 语义；改为**记录最长等待**，若出现饥饿再讨论。

### D9 指标与安全口径 — 推荐双轨
- 论文 Eq.(2) 是"实际行程时间 − 自由流时间"，Eq.(3) 是"**每个时刻对当前活跃车辆求平均**"
  （截面平均）。这两个**不是同一个量**。
- 建议：`tripinfo.timeLoss`（逐车）+ 自采截面平均（逐时刻）**都算**，
  论文里只引用一个并写明定义。这条同时决定 R2-6（sqrt 轴）怎么答。
- 安全：`--collision.action warn --collision.check-junctions true`，
  并**分列**"交叉口内部"与"出口汇流"两类碰撞。

### D10 车流落地 — 推荐"保持 σ=1.0 + 截断负间隔"
- 高密度档（直行间隔 < 3 s）在 `normal(μ,1.0)` 下会抽到负间隔，SUMO 会变成"立即出发"，
  造成成批同时发车。
- 截断到 `≥ 0.1 s`（= 步长）只处理不可能值，**不改变输入分布**；截断比例要记录并报告。
- `departLane` 保持 `first`（不改输入，与投稿一致），出口汇流交给 D3。

### A1 右转策略（顺带回应 R1-F3）— 推荐"一视同仁"
- 无信号环境下不存在"右转常绿"，只有资源预约。右转车与其他 movement 一样排队。
- 这句话本身就是**回答 R1"为什么右转常绿"的最佳素材**：
  "论文 Table II 的 Always Green 是**信号基线**的规则描述，不是本文方法的设定；
  本文方法里所有 movement 一视同仁。"

### A2 不做 `Δt_safe` 敏感性
- 会被读成消融；只报主值 + 一句"更宽松取值提高吞吐、降低安全裕度"即可。

## 6. 附录 A：两项零新增文件的实测验证（2026-11-02）

按"改动最小"原则，下列验证**没有新建任何场景文件、没有新建任何代码文件**，
命令原文写在这里即可复现。

### A1. 0.1 s + 原始三件套（命令行覆盖，不动 cfg）

```bash
sumo -n scenarios/original/cross3.net.xml \
     -r scenarios/original/routes.rou.xml \
     -a scenarios/original/types.typ.xml \
     --begin 0 --end 100 --step-length 0.1 --seed 81890 \
     --no-step-log true --collision.action warn --duration-log.statistics true
```

**结果（实测）**

| 项 | 值 |
|---|---|
| 退出状态 | 正常结束（`Simulation ended at time: 100.00`） |
| 载入 | **无 XML/属性错误** → `departInterval` 在 SUMO 1.12.0 下**被接受** |
| Inserted / Running | 80 / 6 |
| **Collisions** | **2**，均在 `center2south_0`（**出口车道汇流**：`flow_ns.0` 直行 vs `flow_ws.0` 右转） |
| TimeLoss / Speed | 4.31 s / 9.73 m/s |

**结论**

1. **0.1 s 不需要新建 `.sumocfg`**，命令行覆盖即可 → 满足"改动最小"。
2. 即使是轻载样例（≈ MaxD/10），**出口汇流碰撞依然出现** → 再次确认
   **D3 的资源集必须包含出口车道**，只预约交叉口内部不够。

### A2. `setStop` / `resume` 在 0.1 s 下是否真的能拦住车（验证 D5）

同一命令行 + TraCI：在 `east2center` 上取一辆距停止线 > 25 m 的车，
`setStop` 到 `车道长 − 2.0 m`，观察 20 s，然后 `resume`。

**结果（实测）**

| 检查项 | 实测 | 判定 |
|---|---|---|
| 停放后 20 s 内是否进入交叉口 | **否**（`roadID` 始终 = `east2center`） | ✅ |
| 是否停在停止线前 | 是（`lanePos = 84.40`，`laneLen = 86.40`） | ✅ |
| `resume` 后是否放行 | 是（`t = 22.3 s` 进入 `:center_6`） | ✅ |

**结论**：**D5（`setStop` 到停止线 + 批准后 `resume`）在 0.1 s 下可用**，
且被拒绝的车辆不会越过停止线。

**副作用已确认**：`setStop` 会写 `stopTime` → **D9 的"双轨指标"是必要的**，
`tripinfo` 的原生字段不能直接当效率指标用。
